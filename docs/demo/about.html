tfplanlens

Read a Terraform plan the way a reviewer needs to: deletes and replaces first, with the reason in plain English.

A small Go CLI that reads the JSON from terraform show -json and reports what matters. It works offline: no AWS credentials, no Terraform binary, no network, no LLM. The output is deterministic.

try it in 30 seconds

# Go 1.23+. There are no releases yet, so install from a clone.
git clone https://github.com/aalaydrus/tfplanlens && cd tfplanlens
go install ./cmd/tfplanlens

terraform plan -out plan.bin
terraform show -json plan.bin > plan.json
tfplanlens report plan.json

what you get

== Danger ==
! REPLACE aws_dynamodb_table.orders [STATEFUL]
    type: aws_dynamodb_table | target account: 123456789012 (source: allowed_account_ids)
    why: Attribute change forces replacement: range_key, hash_key
! REPLACE aws_secretsmanager_secret_version.db
    why: Attribute change forces replacement: secret_string
! DELETE aws_sqs_queue.orders["bulk"]
    why: for_each key removed: bulk
    WARNING: for_each key removed while sibling instances change (possible key rename: …)

That is real output from the orders-platform example (a made-up stack on an AWS emulator, with dummy account IDs).

Danger first

Every delete and replace with the reason, a STATEFUL badge, and a warning when a count or for_each change looks like an accidental shift.

Which account

Where terraform apply runs versus where each resource lands, and how that was decided.

Short

Long values become the lines that changed. Unknown values are counted, not printed.

And also

Drift, moves, imports, apply waves, a diff between two plans, several plans in one report, and an interactive tui.

why not just read terraform plan

For a small plan you should. It gets hard when the plan is big or noisy. In one real plan we measured, Terraform's output was 105 lines and 25,835 characters, with a single line of 14,705 characters: a base64 user_data shown before and after. The tfplanlens text report for the same plan was 58 lines and shows the decoded change as 2 lines removed and 2 added out of 401. That is a summary, not a replacement: it does not list unchanged attributes or every create.

commands

tfplanlens report plan.json -f html -o report.html      # one offline HTML file
tfplanlens report plan.json -f markdown -o report.md    # a PR comment
tfplanlens report plan.json --fail-on delete,replace:aws_db_instance   # exit 1 in CI
tfplanlens report a.json b.json                         # several plans, one report
tfplanlens diff before.json after.json                  # what the new push changed
tfplanlens tui plan.json                                # explore interactively

Settings such as the apply account, default formats and --fail-on rules go in an optional tfplanlens.config.yaml.

design rules

  • Offline and deterministic. The same plan gives the same report.
  • Sensitive values are never printed. Values Terraform marks sensitive are hidden, and secret-looking values it does not mark are redacted by name and by shape.
  • Say "unknown" when the plan cannot tell. The backend, local.* references and cross-plan dependencies are not in the plan, so the tool does not guess.
  • Danger before anything else. A test enforces this.
  • Arrays are [], never null in the JSON output, so scripts do not break.
  • A small CLI. A test lists the flags report is allowed to have.

limits

  • Redaction is best effort. It cannot catch every secret, and the docs list what is and is not hidden. Plan files themselves contain secrets in plain text: never commit one.
  • The tool reads one plan (or several you give it). It cannot see who else uses a resource, or which commit caused a change.
  • Apply waves are a lower bound: replace_triggered_by and local.* references are not in the plan JSON.
  • It has been tested on real Terraform plans, but the AWS examples come from an emulator, not a real account.
  • No releases yet; install from a clone.
